# Результаты очистки и расширения метрик

Работа выполнена по [плану](cleanup-and-design-plan.md), составленному после
изучения сессий и истории `code-metrics-toolkit`. Исходная точка этого репозитория —
`e62a56f`; изменения разделены на исправления, перенос обязанностей и новые метрики.

## Структура и владение

- Каталог определяет ID, version, unit и допустимые target kinds. Проекторы больше
  не повторяют метаданные; hotspot ranking использует опубликованные metric rows.
- Roslyn traversal находится в `Syntax`, orchestration/workspace — в `Analysis`,
  формулы и ranking — в `Metrics`, запись артефактов — в `Reporting`.
- Имена `AnalysisFacts`, `AnalysisFactsCollector`, `MemberLength`, `TokenLineCount`
  и `Core.Contracts` соответствуют содержимому и владельцам.
- Диагностики владеют списком и индексом; fallback project/file membership имеет
  одного владельца. Summary рассчитывается в одном месте, а настройка chunk text
  берётся только из `AnalyzeRequest`.
- Исключения директорий согласованы между discovery и isolation. Общий лимит
  записей принадлежит контракту, локальные лимиты чтения остались у читателей.
- Scoring-тесты разделены по проверяемым контрактам. Проверки зависимостей защищают
  независимость Scoring, отсутствие artifact/orchestration dependencies в Facts
  и файлового I/O в metric projections.

Переименование публичных Core C# типов требует обновления imports и callers,
компилирующихся против исходников Core. В `SourceSpanFacts` требуется `StartColumn`
для точной идентичности деклараций. Отдельного опубликованного пакета Core нет.
Постоянный слой устаревших алиасов не добавлен.

## Исправления поведения

| Изменение | Что теперь измеряется |
| --- | --- |
| Partial type | `type_count` файла считает физические декларации один раз, включая shared sources; graph сохраняет логический type target |
| Partial method | Definition и implementation образуют один логический member |
| Явные type tests | Поддержанные явные type patterns учитываются в decision points; constant/null patterns исключены |
| Многострочные литералы | Token lines покрывают весь span; whitespace внутри токена не считается blank line |
| Вложенный временный каталог | Isolation исключает собственную временную копию из обхода |
| Windows paths | Rooted результат relative-path проверки не принимается за путь внутри входного дерева |

Это исправления существующих документированных формул; их metric versions
сохранены. Значения и производные агрегаты на затронутых входах могут измениться.
`hotspot_rank` получил **2.0.0**: недоступные компоненты исключаются, оставшиеся
веса нормализуются. Отсутствующая semantic-метрика больше не превращается в ноль.

## Дополнения и совместимость

Первый этап расширения включает зависимости и циклы проектов/namespaces,
дублирование с координатами регионов, weighted member complexity и распределения
размера/сложности на уровне проекта и решения. Формулы и ограничения находятся в
[каталоге](../../src/CodeMetricsToolkit.Core/Metrics/README.md).

В каталоге **66 метрик** вместо исходных 50: 8 добавлены для project/namespace
dependencies, 3 для duplication и 5 для агрегатов. Существующие max/p95 сложности
также доступны для проектов и решения.

Шесть существующих метрик зависимостей типов переходят на **1.1.0**: входной граф
теперь включает зависимости деклараций, полей, сигнатур, атрибутов и обращений
к статическим членам. `type_coupling` и метрики вызовов сохраняют свои определения.

Артефакты и пакеты переходят на **0.2.0**. Новая vocabulary графа требует
перегенерации артефактов и `artifactContractVersion: "0.2.0"` в Scoring profiles.
Chunk IDs теперь включают стартовую колонку, устраняя коллизии двух деклараций
на одной строке. Версия самого формата scoring profile остаётся **1.0.0**. Совместное чтение
артефактов нескольких версий не добавлено.

## Сохранённые границы

LCOM, Git/coverage ingestion, unused-symbol search, Halstead/MI, batch analysis,
новые встроенные веса hotspots и отдельная baseline CLI не входят в этот этап.
Это отложенные пункты исходного плана. Универсальный «балл чистоты» не вводился.

Analyze parser оставлен локальным: второго потребителя или дублирующего parser
нет, а отдельный framework не устраняет выявленную ошибку. Scoring сохраняет
собственный небольшой reader и DTO, чтобы не зависеть от Core/Roslyn.

Архитектурные проверки защищают выбранные границы; они не доказывают отсутствие
всех code smells. Performance smoke не является гарантией стоимости для любых
размеров и структур входа.

Duplication ограничен 500 000 токенами, 500 000 окнами и 20 000 000 единицами
работы; превышение завершает весь анализ с ошибкой. Пределы не настраиваются через
CLI. Shared files с разными preprocessor symbols используют первый контекст
анализа, согласованно с остальными метриками физического файла.
