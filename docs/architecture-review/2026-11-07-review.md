# Architecture and metric correctness review — 2026-11-07

The current design is suitable for a deterministic CLI analyzer with versioned file
artifacts and an optional scoring consumer. The strongest boundaries are already in
place: source collection, pure metric projection, publication, validation and consumer
policy. A framework or one interface/project per metric would add indirection without
solving the problems found in this review.

This is a source/test review plus real executions, not a formal proof of correctness or
a calibrated assessment of code quality. The reference checkout was `8d2f172`; the
measurements below include this review's fixes and use Roslyn 5.6.0, SDK 10.0.403 and
macOS arm64. The [previous audit](README.md) retains its own historical graph artifacts.

## Design assessment

| Aspect | Evidence and judgment |
| --- | --- |
| Dependency direction | CLI references Core; Scoring reads the file contract without Core/Roslyn references. Core namespace dependencies are acyclic in both the emitted source graph and the IL-based architecture check. This is appropriate separation for the current product. |
| Metric ownership | `MetricCatalog` owns identities, versions, units and target kinds. Projectors consume facts; ranking consumes their results. New tests forbid Metrics dependencies on Analysis, Syntax and Validation as well as the existing publication/discovery boundaries. |
| Facts versus policy | Raw metrics remain independently usable. Hotspot ranking is explicitly a versioned heuristic; consumer thresholds live in Scoring. Keeping these separate makes comparison and policy changes reviewable. |
| Complexity concentration | `AnalysisFactsCollector` is 695 lines, `CliApplication` 591, and `ScoringEngine` 562. The CLI's `RunAnalyzeAsync` is 238 lines (syntax CC 44, cognitive 83). These are reasonable future extraction points when responsibilities change, but line count alone does not justify a rewrite. |
| Trust boundary | Successful workspace opening did not guarantee framework references. This review adds a minimal framework sanity check. Missing package symbols remain a documented limitation; `trusted` does not mean a successful build. |
| Scale | Iterative SCC processing avoids recursion depth failures. Reachability still materializes sets for branching condensation graphs. Duplication uses fixed passes and hash lookups instead of occurrence pairs; this review removes its arbitrary ceilings after a larger corpus run. Its in-memory indexes still grow with input size. |
| Contract discipline | Golden expectations cover all 66 metrics, and semantic changes below receive metric versions. Artifacts are validated before publication; independently packaged Scoring consumes completed generations. |

The initial source self-analysis selected `src/**/*.cs`: 86 files, 159 logical types, 699
members, 12,842 physical lines and 18,373 metric rows. Four project files were loaded,
including the test project with its source excluded. There were no namespace dependency
cycles. One informational compiler diagnostic (`CS9335`, a redundant exception pattern in
`DotnetRestoreRunner`) elevated that method's hotspot rank. Inspection confirms this is
not evidence of a severe defect: diagnostic severity is not weighted by the current
ranking formula. This is another reason to inspect components before acting on ranks.

## Confirmed correctness findings

| Finding | Observable impact | Resolution |
| --- | --- | --- |
| Value-type inheritance counted runtime bases | Structs reported depth 1 and enums depth 2 despite the class-only contract. | Restrict traversal to classes; `inheritance_depth@1.0.1`. Classes, records and interfaces retain their expected behavior. |
| Diagnostic attribution used only the primary declaration | Diagnostics in other partial files disappeared from logical type/member totals; incomplete source spans were treated as overlapping. | Union all declaration spans, count each diagnostic once per target, require complete coordinates; `diagnostic_count@1.1.0`. Primary location metadata remains stable. |
| Missing framework references could still be trusted | A loaded compilation without `System.Object` produced misleading semantic metrics, diagnostic counts and ranking inputs. | Mark the analysis degraded, retain syntax/raw diagnostics, omit semantic/graph/diagnostic rows and return CLI exit 3. Ordinary source errors with valid framework references remain analyzable. |
| Duplication ceilings aborted a large solution | 980,914 tokens exceeded the fixed 500,000-token cap before matching ran, preventing publication of every metric. | Remove the token/window/work ceilings; keep cancellation and input validation. Exact formulas and metric versions are unchanged. |

Each behavior fix has executable Red/Green evidence. The inheritance/diagnostic group
went from 7 failures in 11 cases to 11 passes. The trust group went from one failure in
two cases to two passes; its companion case protects analysis of genuinely broken source.
Two large-input regressions also failed at the old duplication ceiling before passing:
complete collection on 2.2 million tokens and CLI publication on 500,010 tokens. These
replace three tests for the intentionally removed limit-rejection behavior.

An exploratory run of the original collector with its internal limits raised selected
1,395 files and 980,914 tokens. Two samples took 0.76/0.80 seconds for duplication;
parsing plus collection peaked at 374.7/439.1 MiB RSS (`/usr/bin/time -l`). These are local
observations, not a throughput guarantee or a full semantic-process memory measurement.
No evidence justified the previous numerical thresholds. The remaining practical limit
is available memory, alongside the general input/output validation ceilings.

Documentation also overstated CFG complexity as bare `E - N + 2P` and described ternary
decisions without their nesting contribution. Both descriptions now match the existing
implementation; those formulas were not changed. Exception CFGs demonstrate why the
existing lower bound of 1 matters. The [metric guide](../toolkit/metrics-guide.md)
explains purposes, populations, caveats and relationship graphs for every catalog entry.

## Validation and its limits

- Locked restore, Release build with zero warnings/errors, and 317 passing tests with
  no skips on macOS arm64.
- Exact golden value/version/kind/unit expectations for all 66 metrics, every declared
  target kind represented, and cross-metric ratio/complexity/CFG/cycle invariants.
- All 512 directed three-node graphs, plus 200 seeded graphs up to 16 nodes, checked
  against an independent Floyd–Warshall reference for SCCs and both reachability directions.
- Roslyn-backed cases for value types, records, partial diagnostics, missing spans,
  accessors, constructors, nested operations, exception flow and line-ending variants.
- Tool installation/analysis/validation and independent Scoring consumption from the
  produced NuGet packages, using the repository's package smoke scripts.
- Additional local corpus runs checked source LOC directly and graph arithmetic using
  an independent Python traversal, with source inspection of selected hotspots and cycles.
  Detailed external-source reports remain local; their absence from this public repository
  is not a claim that those codebases have passed quality gates.
- Dependency restore succeeded for all six external solutions in isolated copies.
  Reanalysis produced trusted semantic output for all six, including the full largest
  solution; seven semantic/syntax outputs passed 136,304 independent arithmetic checks.
  Its full semantic run took 42.94 seconds with 1,460.9 MiB main-process peak RSS.

A normal serial build of that largest solution succeeded while the toolkit reported
54 nullable errors in test projects. The toolkit collects raw compilation diagnostics
without executing third-party diagnostic suppressors; the installed assertion framework
provides a not-null suppressor. These observations must not be presented as 54 confirmed
source defects. This difference, and its impact on ranking, is documented explicitly.

The graph oracle validates algorithms, not completeness of Roslyn symbol resolution.
Syntax metrics omit top-level member targets and field/event initializers. CFGs omit
separate nested-function graphs and full exception paths. Call graphs are static and
incomplete for runtime dispatch. Missing metrics are not zero; ranks depend on the
selected population. See [known limitations](../mvp-limitations.md).

No metric plug-in layer, parallel analyzer, scoring policy or budget override was added.
The duplication ceiling was removed at its existing owner. Further loading or scaling
changes should likewise follow measured requirements and regression cases.
